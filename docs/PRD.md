# D-FET Trainer iPad — PRD v0

> 작성 시점: 2026-05-27 · 작성자: 본인 + Claude

## 1. 문제 (Problem)

**현재 트레이너 겸 물리치료사는 회원 세션 기록을 거의 안 한다.**
- 종이 메모는 분실되고, 머릿속 기억은 다음 세션 때 회상되지 않는다
- 결과: 회원은 본인의 진행을 못 보고, 트레이너는 매 세션을 "처음"처럼 시작
- "회복 진행률"이나 "운동 처방 변화"가 트레이너-회원 양쪽 모두에게 보이지 않음

**진짜 문제 재정의**:
> "복잡한 SOAP 도구가 없다"가 아니라
> **"기록의 마찰이 커서 기록 자체가 시작되지 않는다"**

그래서 v0의 설계 원칙은 **마찰 ≈ 0**. 풀폼 SOAP·ROM/MMT 정량 입력·차트 자동화는 v0에서 모두 빼고, "세션 직후 30초 안에 한 줄 남기기"가 가능해야 한다.

## 2. 사용자 (User)

**페르소나**: 트레이너 겸 물리치료사 (하이브리드)
- 한 명의 회원에게 운동 코칭 + 임상 평가를 동시에 수행
- iPad 9.7~13인치 + Apple Pencil 사용
- 세션은 30~60분, 평균 하루 5~8명
- 현재 기록 도구: 종이/머릿속 (체계 없음)

**비-페르소나** (v0 타겟 아님):
- 헬스장의 일반 PT 트레이너 (세트/레프/무게 위주 — 운동 라이브러리가 핵심)
- 대형 병원 물리치료사 (전자차트 EMR 연동이 핵심)

## 3. 출시 범위 (Scope)

| 단계 | 사용자 수 | 시점 | 검증 기준 |
|------|-----------|------|-----------|
| v0 alpha | 본인 1명 | 슬라이스 1~3 후 | 본인이 1주 매일 쓴다 |
| v0 beta | 동료 1~2명 | 슬라이스 4~5 후 | 2주간 매일 1건 이상 기록 |
| v0 release | 한 센터 (5~10명) | 슬라이스 6~ 이후 | 센터 평균 회원당 주 1회 이상 기록 |

> 한 센터 = 본인이 소속/연결된 단일 센터. 멀티 센터/B2B는 v0 비-목표.

## 4. v0 하루 한 사이클 (Daily Cycle)

```
출근
 └→ [출근 시] 오늘 볼 회원 목록 한 번 확인 (선택)
세션 진행
 └→ [세션 직후 30초] iPad 꺼내 회원 1명에 메모 1줄 + 다음 세션 계획 1줄 남김
        ↓
        회원 앱에서 회원이 그 메모를 본다 (트레이너-회원 사이클 닫힘)
퇴근
```

이 흐름이 **하루 5~8회 일어난다**. 한 사이클의 마찰이 작아야 누적 효과가 생긴다.

## 5. v0 슬라이스 순서 (Build Order)

매 슬라이스는 **백엔드 연동 + 종단 검증**까지 완료해야 다음으로 넘어간다.

### 슬라이스 1: 트레이너 인증 + 본인 담당 회원 목록
- iPad 앱에서 이메일/비밀번호 로그인
- 본인이 담당하는 회원 목록 표시 (`trainers/{uid}.memberIds[]`)
- 다른 트레이너의 회원은 보이지 않음 (Firestore 규칙 검증)
- **검증**: 트레이너 A는 자기 회원만 보이고, 트레이너 B의 회원 문서는 거부됨

### 슬라이스 2: 회원 한 명에 메모 1개 작성/저장
- 회원 탭 → 단일 텍스트 필드 → 저장 버튼 1개
- 다른 입력 없음 (제목·태그·메트릭·날짜 자동)
- **검증**: 본인이 5초 안에 메모 작성 → 저장 → 목록 갱신 확인 (실측)

### 슬라이스 3: 회원 앱에서 트레이너 메모 보기
- Flutter 회원 앱 [member_soap_notes_screen.dart](../lib/widgets/member_soap_notes_screen.dart) 또는 신규 화면에서
- 트레이너가 작성한 메모 중 `isSharedWithMember == true`만 표시
- **검증**: 트레이너 작성 → 회원이 본인 앱에서 1분 안에 확인

### 슬라이스 4: 다음 세션 계획 1줄 (homework / next plan)
- 메모 옆에 "다음 세션 계획" 별도 텍스트 1줄
- 다음 세션 시작 시 자동으로 상단 표시
- **검증**: 트레이너 A가 회원 X의 다음 세션 계획을 작성 → 1주 후 그 회원 다시 클릭 시 가장 먼저 보임

### 슬라이스 5: 회원 추가/배정 흐름
- 관리자가 회원 이메일로 트레이너에게 배정 (`assignMemberToTrainer` Cloud Function)
- 트레이너 앱에서 새 회원이 즉시 목록에 추가됨 (실시간)
- **검증**: 새 회원 가입 → 관리자가 배정 → 트레이너 앱 새로고침 없이 노출

### 슬라이스 6 이후 (v0 release 이후로 미룸)
- Apple Pencil 자유 필기 (PencilKit) — 일부 트레이너는 손글씨가 빠름
- 사진 첨부 (자세 사진, 운동 동영상)
- ROM/MMT 정량 입력 (필요 트레이너만)
- 통증 척도 0~10 트래킹
- 운동 라이브러리 / 운동 처방 카드
- 주간 리포트 / 차트
- 트레이너 위젯 (오늘 세션 카운트)

## 6. v0 비-목표 (Out of Scope)

- 풀 SOAP 폼 (Subjective/Objective/Assessment/Plan 구조화) — 기록 자체가 시작된 후 슬라이스 N에서 도입
- 운동 라이브러리 / 운동 영상
- 결제/구독 (베타 동안 무료)
- 그래프·차트 자동 생성
- 다중 센터 / 트레이너 간 회원 공유
- 트레이너 커뮤니티
- AI 추천 (회원 측 AI 영양분석은 별개 — 회원 앱 유지)

## 7. 성공 지표 (v0 Success Metrics)

| 지표 | v0 alpha (본인) | v0 beta (2~3명) | v0 release (5~10명) |
|------|-----------------|------------------|----------------------|
| 일일 활성 트레이너 비율 | 100% (본인) | 80%+ | 70%+ |
| 트레이너당 일 기록 수 | 5~8건 | 평균 5건 | 평균 3건+ |
| 회원이 메모를 본 비율 | — | 50%+ | 60%+ |
| 슬라이스당 종단 검증 통과 | 100% (must) | 100% (must) | 100% (must) |
| 평균 메모 저장 시간 | < 10초 | < 10초 | < 10초 |

> 평균 저장 시간이 핵심 KPI. 30초를 넘어가면 기록 습관이 무너진다.
