# D-FET UI/UX 전면 개편 PRD

> 문서 버전: v1.0 Draft  
> 작성일: 2026-08-09  
> 대상: Flutter 회원 앱(iOS 우선, Android 동등 지원) + 트레이너 핵심 접점  
> 디자인 방향: **D-FET Signal Path**  
> 상태: 이미지 프로토타입 검토 전

---

## 1. 제품 한 문장

> D-FET은 건강 수치를 보여주는 앱이 아니라, 사용자가 자신의 생활 실천과 4축 건강 데이터의 변화를 연결해 보고 다음 행동을 선택하게 하는 통합 케어 도구다.

4축은 다음과 같다.

| 축 | 의미 | 식별색 | 대표 경험 |
|---|---|---:|---|
| 운동 | 움직임·운동 수행·신체 활동 | Motion Blue `#3478F6` | 운동 기록, 수행 추이, 자세 피드백 |
| 식단 | 섭취·영양·식이 행동 | Nutrition Orange `#F59E45` | 빠른 식단 기록, 식이섬유·영양 행동 |
| 장 | 장내미생물 검사·장 건강 | Gut Violet `#8A6FE8` | 16S 결과, 다양성, 구성, 변화 비교 |
| 혈액 | 혈액 POCT·생화학 지표 | Blood Coral `#E85D68` | 13종 바이오마커, 패널, 추이 |

축 색상은 데이터의 출처를 식별하는 데만 사용한다. 성공·주의·오류 상태는 별도의 의미 색과 문구를 사용하며, 색만으로 상태를 전달하지 않는다.

## 2. 개편 배경과 문제 정의

### 2.1 현재 경험의 문제

1. **점수와 카드가 많지만 사용자의 다음 행동이 늦게 보인다.**
   - 사용자는 첫 화면에서 여러 숫자를 해석해야 한다.
   - “그래서 오늘 무엇을 하면 되는가”가 데이터 아래로 밀린다.

2. **모든 정보가 비슷한 흰색 라운드 카드로 표현된다.**
   - 중요도, 데이터 출처, 행동 가능 여부의 차이가 약하다.
   - 다른 웰니스 앱과 구별되는 D-FET 고유 인상이 부족하다.

3. **운동·식단·장·혈액의 관계가 화면 구조에서 드러나지 않는다.**
   - 축별 색과 아이콘이 일부 적용됐지만 화면 전체의 탐색 언어로 이어지지 않는다.
   - 통합 인사이트가 별도 기능처럼 보이고 일상 기록과 연결감이 약하다.

4. **사용자의 노력이 효능감으로 환원되는 순간이 적다.**
   - 기록 완료, 연속 실천, 검사 전후 변화가 하나의 서사로 묶이지 않는다.
   - 점수가 변하지 않거나 데이터가 부족하면 사용자가 실패로 해석할 수 있다.

5. **임상 데이터와 생활 행동의 표현 수준이 섞인다.**
   - 참고용 수치, 승인 정책에 따른 판정, 사용자의 행동 체크가 시각적으로 충분히 구분되지 않는다.

6. **트레이너 경험은 정보 밀도가 높은데 우선순위가 약하다.**
   - 작은 화면에서는 탭과 내용의 위계가 무너질 수 있다.
   - 세션 직후 빠른 기록이라는 핵심 작업보다 분석 정보가 앞설 위험이 있다.

### 2.2 해결해야 할 핵심 질문

> 사용자가 앱을 열고 10초 안에 “내가 좋아진 부분, 오늘 할 한 가지, 그 제안의 근거”를 이해할 수 있는가?

## 3. 목표와 비목표

### 3.1 제품 목표

- 홈 진입 후 10초 이내에 변화와 오늘 행동을 이해한다.
- 운동·식단 기록은 15초 이내에 완료할 수 있다.
- 검사 결과는 소비자용 요약과 전문가용 근거가 명확히 분리된다.
- 사용자가 기록 완료와 검사 전후 변화를 통해 효능감을 느낀다.
- 네 축을 색·아이콘·레이아웃으로 일관되게 식별한다.
- 320px 폭, 글자 2.0배, 라이트·다크 모드에서도 정보 위계가 유지된다.
- Flutter의 동일 컴포넌트 계약으로 iOS와 Android를 제공한다.

### 3.2 비목표

- 승인되지 않은 임상 점수나 인과관계를 새로 만들어내지 않는다.
- 모든 데이터를 한 화면에 최대한 많이 노출하는 전문가 대시보드를 만들지 않는다.
- 네 축 아이콘을 성공·경고·설정·탐색 등 모든 의미에 남용하지 않는다.
- 관리자 웹 전체 개편은 이 PRD의 구현 범위에 포함하지 않는다.
- SwiftUI 트레이너 앱 전체 재설계는 포함하지 않으며, 핵심 기록 흐름만 디자인 계약을 정의한다.

| 세션 직후 | 어떻게 빨리 남기지? | 30초 이내 한 줄 기록과 다음 계획 저장 |
| 회원 변화 검토 | 무엇이 함께 변했지? | 4축 중 관련 축과 시점만 압축해 표시 |

## 5. 성공 지표

### 5.1 북극성 지표

**주간 의미 있는 케어 루프 완료율**

다음 세 단계 중 2개 이상을 한 주에 완료한 활성 회원 비율로 정의한다.

1. 운동 또는 식단 기록
2. 오늘의 행동 완료 체크
3. 리포트 또는 변화 근거 확인

### 5.2 보조 지표

| 지표 | 목표 |
|---|---:|
| 홈 → 오늘 행동 확인 시간 | 중앙값 10초 이하 |
| 빠른 기록 완료 시간 | 중앙값 15초 이하 |
| 오늘 행동 완료율 | 노출 사용자 중 35% 이상 |
| 완료 후 7일 재방문율 | 기존 대비 +15% |
| 검사 리포트 상세 진입률 | 요약 열람자의 30% 이상 |
| 데이터 부족 화면 이탈률 | 기존 대비 -20% |
| 접근성·렌더 오류 | 출시 차단 기준 0건 |

효능감은 단순 점수 상승이 아니라 “내가 한 행동이 기록되고 다음 확인 시점이 보이는가”로 측정한다.

## 6. 정보 구조

운영용 회원 앱의 하단 구조는 네 개로 고정한다.

| 탭 | 목적 | 대표 콘텐츠 |
|---|---|---|
| 오늘 | 변화와 한 가지 행동 확인 | 변화 헤드라인, 오늘 행동, 4축 신호, 최근 데이터 |
| 기록 | 운동·식단을 빠르게 남김 | 빠른 추가, 오늘 타임라인, 미완료 항목 |
| 리포트 | 근거와 전후 비교 확인 | 통합·운동·식단·장·혈액 리포트 |
| 내 정보 | 케어 환경과 권한 관리 | 케어유형, 트레이너 연결, 동의·보안, 테마 |

### 6.1 축 아이콘 사용 규칙

- 하단 전역 탐색에는 `오늘·기록·리포트·내 정보` 의미 아이콘을 사용한다.
- 축 아이콘은 리포트 필터, 데이터 출처, 변화 칩, 행동 연결축에 사용한다.
- 장이나 혈액처럼 탭 자체가 축인 임상 데모에서는 축 아이콘을 사용할 수 있다.
- 비활성 축은 회색 단색, 선택 축은 원래 축 색으로 표시한다.
- 다크 모드에서는 네이비 선이 사라지지 않도록 축 색 단색 변형을 사용한다.

## 7. 새로운 디자인 언어: D-FET Signal Path

### 7.1 핵심 개념

네 축 아이콘이 공유하는 **열린 U자 측정 베이스와 하단 노드**를 화면 전체의 구조로 확장한다.

- **Signal Node:** 사용자의 기록, 검사, 행동 완료가 하나의 노드가 된다.
- **Signal Rail:** 시간 또는 근거의 흐름을 얇은 선과 노드로 연결한다.
- **Evidence Ribbon:** 판정 근거·데이터 완성도·정책 버전을 화면 하단 리본으로 분리한다.
- **Action Pulse:** 오늘의 행동은 카드 목록 중 하나가 아니라 화면의 명확한 주 행동으로 표현한다.
- **Axis Lens:** 네 축 필터를 바꾸면 같은 정보 구조에서 색·아이콘·데이터만 전환된다.

### 7.2 기존 카드 중심 UI와의 차이

| 기존 | 개편 |
|---|---|
| 비슷한 둥근 카드의 반복 | 한 화면에 주 표면 1개, 보조 그룹 2개 이하 |
| 점수부터 제시 | 변화 문장 → 행동 → 근거 순서 |
| 초록색 중심의 상태 표현 | 축 색은 출처, 초록색은 완료 상태에만 사용 |
| 아이콘이 장식 역할 | 아이콘이 데이터 축과 이동 경로를 식별 |
| 모든 상세 정보 상시 노출 | 요약 → 근거 펼치기 → 전문가 보기의 단계적 공개 |
| 독립된 기록과 리포트 | 기록 노드가 이후 리포트 타임라인에서 다시 등장 |

### 7.3 시각적 서명

- 배경은 차가운 아이보리/블루그레이의 넓은 캔버스다.
- 카드 테두리 대신 축 색의 짧은 **노드 스트립**과 얇은 경계로 출처를 표시한다.
- 주요 수치는 크게, 설명은 한 문장으로 제한한다.
- 큰 라운드는 핵심 행동 영역에만 사용하고, 데이터 행은 작은 반경으로 밀도를 높인다.
- 그림자보다 명도차와 1px 경계를 우선한다.
- 이모지, 기본 클립아트, 과도한 유리 효과는 사용하지 않는다.

### 7.4 타이포그래피

- 한글 UI·본문은 `IBM Plex Sans KR`을 사용한다.
- 변화 헤드라인·오늘 행동·리포트 핵심 제목은 `Gowun Batang Bold`를 제한적으로 사용한다.
- 큰 점수·변화량·영문 바이오마커는 `IBM Plex Mono`를 사용한다.
- 큰 수치와 표에는 tabular figures를 적용해 자릿수를 정렬한다.
- 현재 전역 `Outfit` 적용과 플랫폼별 한글 fallback은 제거한다.
- 상세 비교와 구현 규칙은 [`FONT_RESEARCH_2026.md`](FONT_RESEARCH_2026.md)를 따른다.

## 8. 화면별 제품 요구사항

### 8.1 오늘 홈 — `Today Signal`

#### 목적

사용자가 앱을 열자마자 변화와 다음 행동을 이해한다.

#### 상단부터의 순서

1. **인사와 데이터 신뢰 상태**
   - 이름, 마지막 동기화 시점
   - 합성 데이터/운영 데이터 표시
2. **변화 헤드라인**
   - 예: `지난 검사 이후 4개 축 중 3개가 좋아졌어요`
   - 점수보다 자연어를 먼저 표시
3. **4축 Signal Rail**
   - 운동·식단·장·혈액 아이콘과 현재 방향
   - 증가·유지·데이터 필요를 아이콘+문구로 표현
4. **오늘의 한 가지 Action Pulse**
   - 행동명, 예상 시간, 연결 축, 완료 버튼
   - 완료하면 같은 영역에서 즉시 완료 피드백
5. **다음 확인 시점**
   - 예: `7일 더 기록하면 식단–장 흐름을 다시 확인할 수 있어요`
6. **최근 근거 요약**
   - 최신 장/혈액 검사 또는 운동/식단 주간 기록 중 중요 항목 2개 이내

#### 필수 상태

- 첫 사용: 점수 대신 기준점 생성 안내
- 일부 축 누락: 완성도와 누락 축, 얻는 방법 표시
- 승인 정책 없음: 수치는 표시하고 `산정 준비 중`
- 행동 완료: 체크, 햅틱, 완료 시각, 취소 가능
- 오프라인: 마지막 동기화 기준임을 명시

### 8.2 기록 — `Quick Capture`

#### 목적

운동과 식단 기록을 15초 안에 완료하고 기록의 축적 효과를 보여준다.

#### 구성

1. 상단에 운동·식단 두 개의 큰 빠른 추가 영역
2. 오늘의 Signal Rail에 시간순 기록 노드 표시
3. 최근 입력을 한 번 탭해 반복 기록
4. 사진 분석은 보조 흐름으로 제공하고 수동 입력 경로를 항상 유지
5. 저장 직후 다음 피드백 제공
   - `오늘 식단 기록 2/3`
   - `이 기록은 다음 장 건강 비교에 함께 사용돼요`

#### 상호작용

- 한 손 엄지 영역에 추가 버튼 배치
- 최근 항목 길게 누르기 없이 명시적 `다시 기록`
- 저장 후 전체 화면 모달 대신 1.2초 성공 피드백과 타임라인 삽입
- AI 신뢰도가 낮으면 자동 저장하지 않고 검토 단계 제공

### 8.3 리포트 허브 — `Evidence Library`

#### 목적

통합 결과와 축별 근거를 같은 탐색 규칙으로 비교한다.

#### 구성

1. 통합·운동·식단·장·혈액 Axis Lens
2. 선택 기간: 최근 / 4주 / 12주 / 검사 사이
3. 변화 요약 문장
4. 비교 가능한 근거 카드 최대 3개
5. 데이터 완성도와 정책 버전 Evidence Ribbon
6. `전문가 상세`는 권한이 있는 사용자에게만 별도 진입

#### 규칙

- 축이 누락되면 레이더 0점으로 오해시키지 않고 점선·빈 노드로 표시
- 서로 다른 정책 버전은 한 숫자로 직접 비교하지 않음
- 생활 기록과 검사 결과는 인과가 아닌 `함께 관찰됨`으로 표현

### 8.4 장 리포트 — `Gut Map`

#### 소비자 화면

- 장 축 아이콘과 검사 메타데이터
- 종합 상태, 다양성, 구성의 세 구역
- 복잡한 전문 용어 뒤에 한 줄 번역 제공
- `내 변화`, `또래 범위`, `데이터 품질`을 분리
- 점수만으로 좋고 나쁨을 단정하지 않음

#### 전문가 화면

- PCoA, UniFrac, Genus, alpha metric을 탭이 아니라 목적별 섹션으로 구성
- 원본·정규화·정책 정보를 Evidence Ribbon에 고정
- 회원 화면과 동일한 축 아이콘을 사용하되 정보 밀도만 높임

### 8.5 혈액 리포트 — `Blood Trace`

#### 소비자 화면

- 13종 수신 완성도와 4개 패널 상태를 먼저 표시
- 정상범위는 숫자와 막대, 상태 문구를 함께 표시
- 검토 대기 항목은 점수에서 제외됐음을 명시
- 이전 검사와 같은 단위·정책일 때만 추이를 연결

#### 오류·부분 데이터

- 지원하지 않는 단위: `단위 확인 필요`
- 정상범위 미승인: `범위 준비 중`
- 일부 항목 누락: 전체 점수를 임의 보간하지 않음

### 8.6 내 정보 — `Care Setup`

#### 목적

계정 설정 목록이 아니라 “내 케어가 어떻게 구성돼 있는가”를 설명한다.

#### 구성

- 현재 케어유형과 네 축 활성 상태
- 연결된 트레이너·기관
- 검사 데이터 동의와 보존 정책
- 알림·테마·언어·접근성
- 데이터 내보내기·삭제 요청

설정 항목은 계정, 케어 연결, 개인정보, 화면 환경 네 그룹으로 제한한다.

### 8.7 트레이너 핵심 화면 — `Session Focus`

#### 목적

탭만 보이고 내용이 비는 상황을 방지하고, 세션 직전·직후의 핵심 과업을 우선한다.

#### 구성

- 상단: 오늘 회원 수와 미작성 기록 수
- 좌측 또는 첫 화면: 담당 회원 목록
- 회원 선택 후 첫 영역: 직전 메모와 다음 계획
- 중앙 주 행동: `세션 기록 한 줄`
- 보조 정보: 관련 축 변화 1~2개
- iPad에서는 목록–상세 2열, 작은 폭에서는 단일 열로 자동 전환

#### 렌더 안전 규칙

- `TabView`/탭 컨테이너는 명시적 최소 높이를 가진다.
- 빈 데이터·로딩·오류 상태도 동일한 높이의 콘텐츠 영역을 렌더한다.
- 작은 폭에서 2열을 강제하지 않는다.

## 10. 인터랙션과 모션

- 모션은 변화 이해와 작업 완료를 설명할 때만 사용한다.
- 화면 진입 시 네 축 노드는 40ms 간격으로 순차 등장한다.
- 행동 완료 시 해당 노드가 채워지고 Signal Rail이 다음 확인 시점까지 이어진다.
- 수치 변화는 카운트업보다 이전 값과 현재 값 사이의 짧은 이동으로 표현한다.
- Reduce Motion 설정에서는 모든 전환을 100ms 이하 페이드로 대체한다.
- 햅틱은 기록 저장, 오늘 행동 완료, 위험한 삭제 확인에만 사용한다.

## 11. 콘텐츠 원칙

### 11.1 문장 구조

1. 관찰: `지난 검사 이후 장 다양성이 함께 상승했어요.`
2. 불확실성: `식단 기록과 연관 가능성이 있어요.`
3. 행동: `이번 주에는 식이섬유 기록을 3일 이어가 보세요.`
4. 확인: `다음 검사 또는 7일 기록 후 다시 비교할 수 있어요.`

### 11.2 금지 표현

- `완치`, `치료됨`, `반드시 개선`, `원인은`, `효과가 입증됨`
- 승인 정책 없이 생성된 종합 점수
- 누락축을 추정한 가짜 완성 수치
- 생활 행동과 임상 검사 사이의 직접 인과 단정

### 11.3 데이터 없음 표현

`데이터 없음`으로 끝내지 않고 다음 행동을 포함한다.

- `혈액 데이터가 아직 없어요. 검사 결과가 연동되면 네 축 비교가 완성됩니다.`
- `식단 기록이 2일 더 쌓이면 장 건강과 함께 볼 수 있어요.`

## 12. 접근성·플랫폼 요구사항

- 본문 텍스트 WCAG AA 4.5:1 이상, 큰 텍스트·그래픽 3:1 이상
- 터치 영역 최소 44×44pt
- 글자 배율 1.0, 1.3, 2.0에서 핵심 행동과 수치가 잘리지 않음
- 320, 390, 430px 폭과 iPad split view 검증
- 모든 축 아이콘에 한국어·영어 semantics label 제공
- 그래프는 텍스트 요약과 데이터 표 대체 경로 제공
- iOS VoiceOver와 Android TalkBack의 탐색 순서를 동일하게 정의
- 시스템 테마는 실제 OS 모드를 추종
- 선택, 경고, 완료 상태는 색 외에 아이콘·문구·형태를 함께 사용

- 기관 승인 없는 점수·범위·권고가 production에 표시되지 않는다.

- 320px·글자 2.0에서 주요 CTA와 데이터가 잘리지 않는다.
- 새 디자인의 주요 과업 성공률이 기존 화면보다 낮지 않다.

- Action Pulse의 점선 궤적은 화면 진입과 완료 상태 전환 때 한 번 움직이며, 완료 버튼과 확인 노드는 축 색상으로 자연스럽게 전환된다.
- OS의 동작 줄이기 설정에서는 등장·펄스 모션을 즉시 완료 상태로 처리한다.

### 2026-08-09 — B · 휴먼 신호 타이포그래피 확정

- 앱의 기본 한글 UI는 `IBM Plex Sans KR`, 변화 헤드라인과 오늘 행동 제목은 `Gowun Batang Bold`, 점수와 검사 수치는 `IBM Plex Mono`를 사용한다.
- 세 서체는 Google Fonts 저장소의 동일 커밋에 고정하고 OFL 문서와 함께 앱에 번들해 iOS·Android에서 오프라인으로 같은 결과를 낸다.
- 바탕체는 행동 설명이나 작은 레이블까지 확장하지 않고, 효능감을 전달하는 핵심 문장에만 제한해 임상 정보의 가독성을 유지한다.

### 2026-08-10 — Evidence Report 원자와 리포트 통일
