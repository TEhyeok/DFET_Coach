# D-FET 전수 화면·기능 검수 기록

- 검수일: 2026-08-10
- 기준 브랜치: `feature/integrated-care-2026`
- 기준 문서: `용역 과업지시서_JH_2026 (2).hwpx`
- 배포 대상: Flutter iOS/Android 회원 앱, SwiftUI 트레이너 작업공간, Next.js 관리자 웹
- 판정 원칙: 화면 파일 존재 여부가 아니라 진입 경로, 데이터 연결, 빈 동작, 권한, 오류·빈 상태, 빌드·테스트 증빙을 함께 확인한다.

## 1. 검수 결론

과업지시서 핵심 범위인 케어유형, 4탭 회원 앱, 장내미생물 16S, 혈액 POCT 13종, 4축 통합 인사이트, Firebase 수집·권한, Next.js 관리자 운영 화면은 소스와 자동검증 기준으로 구현되어 있다. 이번 전수검사에서 별도로 발견된 빈 동작과 미완성 흐름 14개를 보완했다.

운영기관이나 스토어 계정 없이는 완료할 수 없는 항목은 개발완료로 오인하지 않도록 `외부 게이트`로 분리했다. 특히 승인 임상정책, 실제 건강데이터 UAT, staging/production 배포, 앱 서명·심사, 구독 영수증 서버 검증은 소스 구현과 별개의 출시 조건이다.

## 3. 이번 전수검사에서 발견·보완한 항목

1. 트레이너 일정·프로그램·알림 탭이 플레이스홀더였음 → 실제 CRUD·집계 화면으로 교체.
2. 트레이너 홈의 일정·SOAP·재평가 값이 고정 숫자였음 → 저장 데이터 기반 파생값으로 교체.
3. iPhone에서 프로그램 헤더가 겹쳤음 → 반응형 세로 헤더와 선택 탭 자동 스크롤 적용.
4. 커뮤니티가 예시 피드만 표시하고 댓글 버튼이 비어 있었음 → Firestore 실시간 피드·상세·댓글 구현.
5. 커뮤니티 좋아요·댓글 수를 클라이언트가 조작할 수 있었음 → 인증 Cloud Functions 트랜잭션과 서버 전용 규칙으로 변경.
6. 회원탈퇴 버튼에 삭제 동작이 없었음 → 인증 계정·프로필·기록·임상문서·업로드 정리 함수 연결.
7. 수분 기록 다이얼로그 결과가 저장되지 않았음 → 로컬·Firestore 저장 및 초기값 복원 연결.
8. 코칭요청 상태명이 모바일과 관리자에서 달랐음 → `pending/in_progress/completed/rejected` 기준 정규화.
9. 관리자 콘텐츠 화면이 추가 전용이었음 → 편집·노출 활성/비활성 추가.
10. 관리자 검사 오류의 수정 동작이 없었음 → 오류 작업에서 기존 결과를 보존하고 다음 revision으로 재수집하는 흐름 추가.
11. 회원 앱 알림 아이콘이 고정 안내만 표시했음 → 코칭·장·혈액·4축 결과를 모은 알림센터와 상세 딥링크 구현.
12. 고단백 식품을 누르면 뒤 화면까지 닫히고 선택값이 무시됐음 → 단일 결과 반환·즉시 식단 저장·축별 전용 아이콘으로 교체하고 회귀 테스트 추가.
13. 커뮤니티·자세요청·아침추천 일부 표면이 라이트 모드에서도 고정 다크색이었고 음식 이모지를 사용했음 → 테마 표면 토큰과 식단 축 전용 아이콘으로 통일.
14. 시뮬레이터 멤버십 화면이 실제 상품처럼 보이는 임의 가격을 노출했음 → 가짜 상품·가격을 제거하고 서버 영수증 검증 완료 전 판매 비활성 상태를 명확히 표시.
15. Android 트레이너 진입이 탭만 보이고 내용이 없는 상태였음 → 요약·회원·SOAP·계정 4개 실제 화면이 있는 폴백 셸로 교체.
16. 트레이너 회원·일정·프로그램이 단말 로컬에만 남았음 → `trainerWorkspaces/{trainerId}` 소유자 기반 Firestore 동기화 추가. 아바타 이미지는 개인정보·용량 보호를 위해 단말에만 보존.
17. 관리자 회원 상세·통계·관리자 승인 화면이 부족했음 → 회원 통합 상세, 실제 운영 통계, Auth custom claims 기반 승인·감사 흐름 추가.
18. 임상 수집 파이프라인이 단위 테스트에만 머물렀음 → 서명 요청부터 원본 Storage, 소비자·전문가 보고서, 4축 스냅샷, 중복·충돌까지 Emulator 종단 테스트 추가.
19. Firebase Functions v7에서 구형 등록 API와 Admin SDK 접근 방식이 런타임 로드를 막았음 → Node.js 22용 v2 callable 어댑터와 모듈형 Firestore API로 교체.

## 6. 최종 판정

과업 핵심 개발 범위는 소스·자동테스트·빌드 기준 `구현 완료`로 판정한다. 다만 이는 실서비스 출시승인과 동일하지 않다. 위 외부 게이트가 닫히기 전에는 실제 건강데이터, 임상 점수, 구독 결제를 production에서 활성화해서는 안 된다.
