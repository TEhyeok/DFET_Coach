PR 본문에 '동결 예외 사유'(허용 사유, 대상 줄, 대체 동작)를 적고 최소 diff로 고친다. 기능 추가, 리팩터링, 스타일 정리는 하지 않는다. 새 트레이너 기능은 `trainer_app/`에만 만든다.

- **통제**: 자동 차단은 두지 않는다(Q-DEV-11-02). 위 경로를 바꾸는 PR에 `freeze-exception` 라벨과 사유가 없으면 병합하지 않는다. DEC-20의 병합 담당 AI도 같은 조건을 확인한다([01 에이전트 권한 경계](../01_AGILE_WORKING_AGREEMENT.md#에이전트-권한-경계) '병합' 행 ④). 동결 예외가 한 스프린트에 2건 이상이면 03 §11 T-11로 재계획한다.
- **라벨**: `freeze-exception`은 DF-902 실행(2026-09-25)으로 저장소에 있다(`gh label list` 확인). 라벨 설명은 아직 `AppDelegate.swift`·`trainer_ios/`만 적고 있어, 위 표의 나머지 경로를 넣는 수정은 소유자가 한다.

## 후속 조치
1. **운영 Firebase 상태(2026-09-25 읽기 전용 조회) — 결정됨(DEC-19, 2026-09-25): 서울 `asia-northeast3`로 옮긴다.** 소유자 지시는 '아시아 리전'이며 서울 지정은 NFR-16에 맞춘 해석이다. `(default)`에 테스트 데이터만 있다는 것은 소유자가 942-1에서 확인할 전제이며, 확인되면 내보내기를 받은 뒤 소유자가 지우고 서울에 다시 만들며(DF-942), 서울 Storage 버킷을 코드가 명시한다(DF-043). 미사용 Enterprise DB 2개는 소유자 결정으로 남았다([V1-00 K-17](../00_README.md#알려진-차이와-남은-일)). 아래는 조회 당시 기록이다.
   - 코드가 쓰는 Firestore `(default)`(STANDARD, 위치 **`nam5` 미국 멀티 리전**)와 Storage의 운영 규칙이 **전부 거부**다. 저장소의 `firestore.rules`·`storage.rules`는 운영에 배포된 적이 없거나 되돌려졌다. 클라이언트 SDK를 쓰는 회원 앱은 운영 Firestore·Storage를 읽고 쓸 수 없다(Functions·admin_web의 Admin SDK는 규칙을 우회). 실사용 중이면 장애이고, 출시 전이면 규칙 첫 배포가 G-03 뒤 과제다.
   - 코드가 쓰지 않는 Enterprise DB 2개(`default`, `dfet`, 위치 `asia-east1`, 2025-11-06 생성)가 있다. 용도 확인 후 유지·삭제를 정한다(비용).
   - `(default)` 위치가 미국이므로 PRD Q-08·G-09(처리방침 국외이전 고지)에 반영한다. Firestore DB 위치는 바꿀 수 없어, 국내·아시아 리전이 필요하면 새 DB로 옮겨야 한다.
   - 등록된 앱: `kr.co.dfet.coach`(iOS·Android), `com.example.*` 2개, Admin Web. `kr.co.dfet.trainer`는 없다(DF-903).
2. 로컬 firebase-tools는 15.x 이상이어야 한다. 14.17.0에서는 e2e가 functions 로드 실패로 떨어졌다([V1-13](../13_DEV_ENVIRONMENT_AND_AGENT_PLAYBOOK.md) 도구 표에 반영).
