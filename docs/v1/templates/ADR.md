## 사용법

- 파일: `docs/v1/adr/ADR-NNN-<kebab-title>.md`. 번호는 기존 최대값 + 1이다(ADR-001~019는 기술 기준선에서 정함).
- 색인은 [V1-04](../04_ARCHITECTURE.md)의 ADR 색인 표에 같은 PR에서 한 줄 추가한다.
- ADR은 PRD 결정(D1~D14)을 **구현 수준에서** 구체화한다. PRD 결정과 충돌하는 ADR은 만들 수 없다. 충돌이 필요하면 PRD 개정이 먼저다(D1~D4는 소유자 재확정).

## 언제 ADR을 쓰는가

| 쓴다 | 쓰지 않는다 |
|---|---|
| 새 의존성(npm·SPM·pub·도구) 추가 | 한 스토리 안의 구현 세부 |
| 저장 방식·동기화·모듈 경계 변경 | 이름 변경, 리팩터링 |
| 배포·릴리스·CI 구조 변경 | 테스트 추가 |
| 보안·개인정보 설계 변경(규칙 헬퍼 구조, 링크 정책, 로그 정책) | 문구 수정 |
| 스파이크가 기본값을 바꾼 경우 | 스파이크가 기본값을 확인만 한 경우(AS-DEV로 충분) |

## 상태 전이

`Proposed` → `Accepted` → (`Superseded by ADR-NNN` | `Deprecated`)

- Accepted ADR은 본문을 고치지 않는다. 오탈자·링크만 고칠 수 있다.
- 바꿀 때는 새 ADR을 만들고, 이전 ADR의 상태 칸만 `Superseded by ADR-NNN`으로 바꾼다.
- 헤더 표의 '상태'(문서 상태)와 본문의 'ADR 상태'는 다르다. 헤더는 `개발 착수 기준(Ready)`, 본문은 ADR 상태를 적는다.
