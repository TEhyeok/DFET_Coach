## 사용법

- 금요일 리뷰 직후 15:20부터 10분([V1-01 스프린트 리듬](../01_AGILE_WORKING_AGREEMENT.md#스프린트-리듬)). 1인 회고이므로 '느낌'보다 **기록된 사실**(일일 기록, 반려 사유, CI 실패, 대기 시간)에서 출발한다.
- 결과는 `docs/v1/sprints/SPRINT_NN.md`의 '## 회고' 절에 붙인다.
- 개선 행동은 **1~2개만** 고르고, 다음 스프린트 계획에서 가장 먼저 확인한다.

## 회고 질문 목록

매번 전부 답하지 않는다. 이번 주 사실에 해당하는 질문 3~4개를 고른다.

| 영역 | 질문 |
|---|---|
| 흐름 | 가장 오래 In review에 머문 PR은? 원인은 검토 시간, CI, 재작업 중 무엇이었나 |
| 흐름 | WIP 한도(에이전트 3, In review 3)를 넘긴 날이 있었나 |
| 에이전트 | 반려 사유 중 지시서가 모호해서 생긴 것은? 템플릿(V1-T08)이나 컨텍스트 팩(V1-13)을 고쳐야 하나 |
| 에이전트 | 범위 밖 수정, 금지 행동 시도, 테스트 skip이 있었나 |
| 에이전트 | Claude와 Codex 중 어느 쪽이 어떤 영역에서 첫 검토 통과율이 높았나(배정 규칙 조정) |
| 품질 | 병합 뒤 발견된 결함이 있었나. DoD의 어느 항목이 놓쳤나 |
| 품질 | 규칙·계약 드리프트(generate --check 실패, 쿼리-규칙 불일치)가 있었나 |
| 게이트 | 외부 게이트 대기 때문에 바뀐 계획이 있었나. 대안은 제때 정했나 |
| 규제·개인정보 | 금지어 경고, 비밀·실데이터 접근 위험, 로그 금지 항목이 발견됐나 |
| 추정 | 점수 추정이 가장 크게 빗나간 스토리는? 이유는(규칙 정독, 실기기, 이식 복잡도) |
| 지속 가능성 | 소유자 작업 시간(리뷰 '소유자 시간' 표)이 계획보다 컸나. 다음 주 약속을 줄여야 하나 |

## 개선 행동 추적 규칙

- 개선 행동이 문서 변경이면 [문서 변경](../01_AGILE_WORKING_AGREEMENT.md#문서-변경) 절차로 PR을 연다.
- 같은 문제가 3스프린트 연속 나오면 단계 종료 검토([V1-T06](PHASE_EXIT_REVIEW.md))의 안건으로 올린다.
- 비밀·실데이터 접근이나 금지 행동이 발견되면 회고를 기다리지 않고 즉시 해당 PR을 닫고, 회고에는 재발 방지 행동을 적는다.
