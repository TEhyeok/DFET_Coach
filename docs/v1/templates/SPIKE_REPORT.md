## 사용법

- 스파이크 이슈는 폼 [spike.yml](../../../.github/ISSUE_TEMPLATE/spike.yml)(GH-06)로 만들고, 착수 전에 아래 '1. 질문'~'4. 방법'을 채운다(DoR).
- 결과 기록 위치
  - 결론이 **기술 결정**이면 ADR([V1-T03](ADR.md))을 새로 쓰거나 기존 ADR을 갱신하고, 보고서는 스파이크 이슈 코멘트로 남긴다.
  - 결론이 **가정·질문**이면 [V1-00](../00_README.md)의 AS-DEV/Q-DEV 목록에 추가한다.
  - 결론이 **표·데이터**(예: DF-039 이식 줄 범위표)면 `docs/v1/spikes/DF-NNN-<slug>.md` 파일로 남긴다(헤더 표준 적용).

## 규칙

- 타임박스는 점수와 같다: 1점 = 1작업일, 2점 = 2작업일. 끝나면 결론이 없어도 멈춘다.
- 시제품 코드는 `spike/DF-NNN-<slug>` 브랜치에만 두고 병합하지 않는다. 병합 대상은 보고서, ADR·AS-DEV 갱신, 재사용할 테스트 하네스뿐이다.
- 실환경 확인이 필요한 스파이크(DF-038 S-09)는 **가상 데이터**로만 하고, 운영 프로젝트 작업은 소유자가 한다.
- 문헌 수치나 정확도 값을 새로 만들지 않는다. 측정했으면 측정 조건과 함께 '자체 측정, 합성 이미지 n장' 식으로 적는다(PRD §0.2).
